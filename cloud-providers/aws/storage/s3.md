# Amazon S3 (Simple Storage Service)

> Object storage with industry-leading scalability, availability, and durability.

## Overview

S3 stores data as objects in buckets. Objects can be 0 bytes to 5TB. Designed for 99.999999999% (11 9's) durability.

## Key Concepts

| Term | Definition |
|------|------------|
| Bucket | Container for objects (globally unique name) |
| Object | File + metadata, identified by key |
| Key | Full path to object (folder/subfolder/file.txt) |
| Version ID | Unique ID when versioning enabled |
| Prefix | Virtual folder path (no actual hierarchy) |
| Object Lock | WORM (Write Once Read Many) protection |

## Storage Classes

| Class | Durability | Availability | Min Duration | Use Case |
|-------|------------|--------------|--------------|----------|
| **Standard** | 11 9's | 99.99% | None | Frequently accessed |
| **Intelligent-Tiering** | 11 9's | 99.9% | None | Unknown/changing patterns |
| **Standard-IA** | 11 9's | 99.9% | 30 days | Infrequent, rapid access needed |
| **One Zone-IA** | 11 9's | 99.5% | 30 days | Infrequent, reproducible data |
| **Glacier Instant** | 11 9's | 99.9% | 90 days | Archive with instant access |
| **Glacier Flexible** | 11 9's | 99.99% | 90 days | Archive, minutes to hours retrieval |
| **Glacier Deep Archive** | 11 9's | 99.99% | 180 days | Lowest cost, 12-48 hour retrieval |

### Glacier Retrieval Options

| Tier | Glacier Flexible | Deep Archive |
|------|------------------|--------------|
| Expedited | 1-5 minutes | N/A |
| Standard | 3-5 hours | 12 hours |
| Bulk | 5-12 hours | 48 hours |

## Lifecycle Rules

```yaml
# Move to IA after 30 days, Glacier after 90, delete after 365
Transitions:
  - Days: 30  → Standard-IA
  - Days: 90  → Glacier Flexible Retrieval
  - Days: 365 → Delete (Expiration)

# Can filter by prefix or tags
Filter:
  Prefix: logs/
  Tags:
    - Key: archive
      Value: true
```

## Versioning

- Bucket-level setting (cannot disable, only suspend)
- Each object version has unique version ID
- Delete creates a "delete marker" (can restore by deleting marker)
- MFA Delete: requires MFA to delete versions (extra protection)

## Replication

| Type | Description |
|------|-------------|
| **CRR** (Cross-Region) | Compliance, lower latency access, disaster recovery |
| **SRR** (Same-Region) | Log aggregation, live replication between accounts |

Requirements:
- Versioning enabled on source AND destination
- Proper IAM permissions
- Only new objects replicated (use S3 Batch for existing)

## Security

### Bucket Policies (Resource-based)
```json
{
  "Version": "2012-10-17",
  "Statement": [{
    "Effect": "Allow",
    "Principal": "*",
    "Action": "s3:GetObject",
    "Resource": "arn:aws:s3:::my-bucket/*",
    "Condition": {
      "IpAddress": {"aws:SourceIp": "192.168.1.0/24"}
    }
  }]
}
```

### Access Control
- **IAM Policies**: User-based permissions
- **Bucket Policies**: Resource-based, cross-account access
- **ACLs**: Legacy, object-level (prefer policies)
- **Block Public Access**: Account/bucket level safety net
- **Access Points**: Named network endpoints with dedicated policies

### Encryption

| Type | Key Management | Use Case |
|------|----------------|----------|
| **SSE-S3** | AWS managed | Default, simplest |
| **SSE-KMS** | AWS KMS | Audit trail, key rotation |
| **SSE-C** | Customer provided | You manage keys |
| **Client-side** | Client manages | Encrypt before upload |

```bash
# Enforce encryption in transit
"Condition": {
  "Bool": {"aws:SecureTransport": "false"}
}
# Deny if not using HTTPS
```

## Performance

### Baseline
- 3,500 PUT/COPY/POST/DELETE per prefix per second
- 5,500 GET/HEAD per prefix per second

### Optimization
- **Multi-part upload**: Required for >5GB, recommended for >100MB
- **S3 Transfer Acceleration**: Uses CloudFront edge locations
- **Byte-range fetches**: Parallel downloads of object parts
- **S3 Select / Glacier Select**: Query data without full retrieval

## CLI Quick Reference

```bash
# Copy file to S3
aws s3 cp file.txt s3://bucket/path/

# Sync directory
aws s3 sync ./local-dir s3://bucket/prefix/

# List objects
aws s3 ls s3://bucket/prefix/

# Copy with storage class
aws s3 cp file.txt s3://bucket/ --storage-class GLACIER

# Enable versioning
aws s3api put-bucket-versioning --bucket my-bucket \
  --versioning-configuration Status=Enabled

# List object versions
aws s3api list-object-versions --bucket my-bucket
```

## Exam Tips

1. **Durability vs Availability**: 11 9's durability for all classes, availability varies
2. **Encryption default**: SSE-S3 is now default for new objects
3. **Cross-account access**: Use bucket policy + IAM role
4. **Requester Pays**: Requester pays for data transfer (not storage)
5. **Object Lock**:
   - Governance mode: special permissions can delete
   - Compliance mode: NO ONE can delete (not even root)
6. **S3 Glacier**: Direct upload via API (not just lifecycle)
7. **Transfer Acceleration**: Uses CloudFront edges, good for global uploads
8. **Multipart upload**: 5GB hard limit for single PUT, 5TB max object
9. **Versioning + Lifecycle**: Can expire previous versions after N days

## Gotchas

- Bucket names are globally unique across ALL AWS accounts
- Deleting a bucket requires it to be empty (including all versions)
- Standard-IA has minimum 128KB charge per object
- Glacier has minimum 90/180 day charge even if deleted early
- Pre-signed URLs inherit permissions of the creator
- S3 has eventual consistency for overwrite PUTS and DELETES
